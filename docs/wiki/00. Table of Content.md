# Table of Contents

Developer documentation for the **CoreMart 26** React monorepo — a pnpm + Turborepo workspace of
two stacked products: `nikkierp/` (the base platform: UI system, MFE shell, auth, view engine)
and `coremart/` (the business layer that extends it).

Read the documents in order; each one assumes the previous.

| # | Document | What it covers |
| --- | --- | --- |
| 01 | [Micro Frontend architecture](<./01. Micro Frontend architecture.md>) | The Shell and the Micro Apps: how a bundle is declared, downloaded, initialized and mounted as a web component. The purpose of every package under `nikkierp/apps`, `nikkierp/libs` and `nikkierp/modules`. Shell ↔ Micro App and Micro App ↔ Micro App communication: the arguments the Shell passes into `init` and into the mounted element, the host-owned services, and the command bus — naming, handler registration, publishing, and lazy module loading. Reaching the bus from outside React via `CommandBus.instance` / `setInstance`, how a Shell implementation registers commands the library cannot name, and the Shell's shared state (the current org id and module) — who writes it, how a module reads it, and why it must not be cached. |
| 02 | [Service and API](<./02. Service and API.md>) | The per-resource service layer: one service module per resource, its never-throw `CommandResponse` contract, and its place between the command handlers and the transport. The standard dynamic-model REST endpoints exposed by the backend and the shared `RestApi` class every service must reuse, plus how to add business-specific calls alongside them. Org-scoped resources: why omitting `org_id` returns nothing rather than everything, and where to fold it in. Schema registration and the `{module}_{entity}` naming rule. |
| 03 | [View engine](<./03. View engine.md>) | Why pages are authored as plain JSON metadata instead of JSX, and what "serializable" and "UI-framework agnostic" concretely require. How the engine works: the contribution registry and its id/conflict/vendor policy, the metadata node types, the render pipeline from `compilePage` to a template's `render`, and late-resolved field renderers. How to develop and register a new component renderer, page template, field renderer or whole view kit, and how a module authors a page from them. The packages and subpaths that serve all this, and the lint zones that hold the boundaries. |
| 04 | [Dynamic schema UI](<./04. Dynamic schema UI.md>) | How a resource form renders itself from the backend model schema, with no per-resource form code. The `meta/schema` fetch and every key of its payload. How `AutoField` maps a `data_type` to an input, and why auto-generated and non-updatable fields render as text or not at all. The rule that turns a `ulid` into a searchable relation select via `to_relations`, how the target names its own records with `record_label_field`, and how the select is populated over the command bus — including why the generic `core.resource.*` command naming is what makes it possible. Exclusive required field groups, why a blank optional field is dropped from the payload rather than validated, the predicate that hides fields and empty blocks, and the repo's casing conventions for payloads, variables, constants and backend-derived types. |
| 05 | [ERP frontend module](<./05. ERP frontend module.md>) | The anatomy of a frontend module: what a micro-app is, the `MicroAppBundle` `init` contract and its five steps, the folder layout, and a full walk of the `identity` module's `user` resource — constants matching the backend Go schema names, the private module store, the `@storeService` CRUD service, generated CRUD command names versus hand-written exceptions, the page as view-engine metadata, and the menu contribution. Then the `storeService` decorator pattern in depth (`@storeAsyncMethod` / `@storeSyncMethod` / unannotated, and why installed methods do not dispatch), the translation-key rule and its backend `langJson` source of truth, the `data-testid` convention, and a checklist for creating a new module. |

## Quick reference

```bash
pnpm dev:coremart      # run the CoreMart web app (turbo → @coremart/webapp)
pnpm check-types       # tsc --noEmit across the workspace
pnpm lint              # eslint --fix over the whole tree
pnpm vitest run        # tests, from inside a package
```

Node >= 22.19, pnpm >= 10.32. `dev` scripts are `bash -c` wrappers using `realpath` — on Windows
run them through Git Bash, not PowerShell. `nikkierp/` is a **git submodule**; edits there are
commits in a different repository.
